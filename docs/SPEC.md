# Groovestone 키감 체험 웹사이트 — 요구사항

## 1. 목표

기존에 제작하다 중단한 Groovestone 키보드 설명 및 키감 체험 웹사이트를 정리하고 완성한다.

단순한 키보드 쇼핑몰 페이지가 아니라, **사용자가 유튜브 영상을 찾아보지 않아도 웹사이트에서 실제 키보드로 타이핑하며 제품별 타건음과 키감을 간접 체험할 수 있는 인터랙티브 웹사이트**가 목표다.

### 이 목표가 함의하는 것

| 원칙 | 설계에 미치는 영향 |
|---|---|
| 유튜브를 대체한다 | 재생 지연이 없어야 한다. 프리로드 필수. 영상보다 빠르게 소리를 들려주는 게 유일한 경쟁력 |
| 실제 키보드로 타이핑한다 | 물리 키보드 입력이 1순위, 화면 키캡 클릭은 보조 |
| 제품별로 비교한다 | 축 전환이 즉각적이어야 한다. 페이지 이동이나 재로딩 없이 |
| 간접 체험이다 | 소리뿐 아니라 시각 피드백(키캡 눌림)이 함께 가야 "느낌"이 전달된다 |

---

## 2. 사용자 시나리오

**구매 검토자** — 제품 목록에서 관심 있는 키보드를 보고, "이 축 소리 듣기"를 눌러 바로 체험 섹션으로 이동해 타이핑해본다. 마음에 들면 공식 스토어로 넘어간다.

**비교 검토자** — 체험 섹션에서 축을 번갈아 바꿔가며 같은 문장을 타이핑해 차이를 확인한다.

**단순 방문자** — 키보드 소개를 읽다가 호기심에 키를 두드려본다.

---

## 3. 현재 구현 상태

### 완료

- Vite + React 빌드 파이프라인 (한동안 완전히 깨져 있었음)
- KLE 기반 키보드 레이아웃 렌더링 (73키)
- 물리 키보드 입력 → 타건음 재생
- 화면 키캡 클릭 → 타건음 재생
- 키캡 눌림 시각 피드백
- 한글 조합 중복 재생 방지, 키 반복 재생 방지
- Web Audio API 기반 재생 (디코드 캐시 / 자동재생 정책 해제 / 로딩·에러 상태 표시)
- 축 선택 UI (레지스트리 기반, 축 추가 시 코드 수정 불필요)
- 제품 목록 + 검색 + 제품→축 연결
- 밀키축 V2 45g 사운드 세트

### 미완

| 항목 | 비고 |
|---|---|
| 코랄축 / 하니축 / 재잘축 사운드 | 레지스트리에 자리만 있고 `available: false`. 파일만 넣으면 됨 |
| 키캡 색상 테마 | `legacy/`에 gray/black/white/silver/beige/rose-gold 셀렉트가 있었으나 미이식 |
| `groovestone-intro.mp3` 활용처 | 브랜드 사운드인데 현재 어디서도 재생하지 않음 |
| 볼륨 조절 | `useKeySound`가 `volume`을 받지만 UI 노출 없음 |
| 모바일 대응 | 물리 키보드가 없어 화면 키캡 클릭만 가능. 레이아웃도 좁은 화면에서 넘침 |
| 배열 선택 | `keyLayouts.js`에 프리셋 1종(`9009_wkltkl`)만 존재 |
| 테스트 | 없음 |
| 접근성 | 키캡이 `tabIndex={-1}`이라 키보드 탐색 불가 (의도적 — Tab 키가 체험을 방해하므로). 대안 필요 |

## 4. 로드맵

### 우선순위 높음 — 목표에 직결

1. **나머지 3종 축 사운드 확보 및 등록**
   비교 체험이 이 사이트의 핵심 가치인데 현재 축이 하나뿐이라 비교가 불가능하다. 가장 중요한 미완 항목.

2. **모바일 대응**
   방문자 상당수가 모바일일 텐데 지금은 사실상 동작하지 않는다. 물리 키보드가 없으므로 화면 키캡 중심 레이아웃과 축소 배열이 필요하다.

3. **축 A/B 비교 모드**
   같은 문장을 두 축으로 번갈아 들려주는 기능. 순차 전환보다 차이가 훨씬 잘 드러난다.

### 우선순위 중간

4. 볼륨 조절 UI
5. 키캡 색상 테마 이식 (`legacy/` 참고)
6. 배열 프리셋 추가 (텐키리스, 65% 등)

### 우선순위 낮음

7. 타건 통계 (타수, 많이 누른 키 히트맵)
8. 인트로 사운드 활용
9. 테스트 도입

## 5. 제약

- **저작권** — 타건음은 Groovestone 제품의 실제 녹음이다. 외부 재배포용 다운로드 기능은 넣지 않는다.
- **파일 크기** — 축 하나당 약 230KB. 축이 늘어나면 전량 프리로드가 부담이 되므로, 4종을 넘어가면 선택된 축만 로드하는 방식으로 전환해야 한다.
- **브라우저 자동재생 정책** — 사용자 상호작용 전에는 오디오가 재생되지 않는다. 페이지 진입 즉시 소리를 내는 연출은 불가능하다.
- **한글 입력** — IME 조합 중에는 `keydown`이 중복 발생한다. `isComposing` 가드가 항상 필요하다.

## 6. 참고

리팩터링 이전의 바닐라 JS 구현이 `legacy/`에 남아 있다.

- `keyboard-script-mac.js` — 현재 사운드 매핑 로직의 원본
- `keyboard-script-win.js` — 윈도우용 분기. 소리 끊김 대응 흔적이 있음
- `script.js` — 축/색상 셀렉트 연동

현재 앱과 연결되어 있지 않으며 참고용으로만 둔다.
